# 武汉赖子麻将 · 游戏资源分析

> 版本 v1.0.0 · 2026-11-06
> 分析对象：`com.wuhanlaizi.yyb` v6.3.4（应用宝渠道包，75.72MB）
> 用途：作为本项目（uni-app + Phaser 3 复刻版）美术、音频与 UI 实现的唯一依据。实现与本文件不一致时，先改实现或同步改本文件，不允许两边各说一套。

## 0. 取证方式与结论

| 步骤 | 工具 | 结果 |
| --- | --- | --- |
| 包信息 / 引擎识别 | `pyaxmlparser` 解 `AndroidManifest.xml` | 引擎为 **Cocos2d-x + Lua**（`org.cocos2dx.cpp.AppActivity`、`assets/src/main.luac`、`LaunchRes.luac`） |
| 清单与资源解码 | `rea decode-android-resources`（apktool 2.11.1） | 解出 1051 个文件，确认 `package_name=com.wuhanlaizi.yyb`、`minSdk 21 / targetSdk 30`、版本号 `60304` |
| 资源包 | 直接读 `assets/res/res.dat` | 59MB，首字节 `66 3B 7E B6` **非 zip 头**，为加密/自定义打包，无明文图片与 Lua 字节码 |
| 字符串资源 | `res/values*/strings.xml` | 无中文业务文案（文案在 `res.dat` 内），静态层拿不到 `武汉/麻将/金币/商城` 等字面量 |
| 结论 | — | **代码层与资源包均不可静态解出**，按既定策略只做「资源层取证 + 界面规格测量」，美术全部按 Style Guide 重绘，不复制原包任何像素与音频资产 |

附带识别到的第三方能力（决定了本项目**不实现**的边界）：腾讯 YSDK（微信/QQ 登录、Midas 支付）、边锋 `replugin` 插件化、Bugly、数数科技 ThinkingData 埋点、广点通 GDT、微信 OpenSDK。本项目为 H5 演示版，登录用账号体系，支付为模拟，不含任何原生 SDK 依赖。

## 5. 玩法规格（与美术同步锁定）

| 项 | 规格 |
| --- | --- |
| 牌张 | 112 张 = 万/筒/条 1-9 各 4 张（108）+ 红中 4 张 |
| 编码 | `1..9` 万、`10..18` 筒、`19..27` 条、`28` 红中（前后端共用） |
| 皮子与赖子 | 发牌后翻一张定皮子，皮子同花色下一张（9→1）为赖子；红中固定是皮子，只能单张杠 |
| 赖子 | 可代任意序数牌；手上留皮子或红中不能胡；小胡最多 1 张赖子，大胡不限 |
| 动作 | 吃（仅下家）、碰、明杠、暗杠、补杠；红中杠 / 皮子杠 / 赖子杠为单张特殊杠 |
| 开口 | 吃、碰、明杠各算一次，未开口不能胡；特殊杠与暗杠不算开口 |
| 胡型 | 4 面子 + 1 将；无七对；小胡必须二五八做将 |
| 番型 | 屁胡 1 底番、碰碰胡 2、清一色 2、将一色 2、全求人 2、杠上花 1、海底捞 1、抢杠 1、硬胡 1、自摸 1、放冲 1、庄家 1、每开口 1、明杠/红中杠/皮子杠 1、暗杠/赖子杠 2；封顶 6 番 |
| 结算 | 底分 × 2^番；一炮单响，点炮者付双份、其余两家各付一份；杠只计番 |

## 6. 一致性核对清单（发版前逐项打勾）

1. 大厅配色与第 1.1 节色板一致，未出现散写色值。
2. 七个玩法卡文案、顺序、角标与源界面一致（武汉麻将/四川麻将/拖拉机/斗地主/卡五星/晃晃/跑得快），且不出现重名卡片。
3. 商城页签、礼包档位（8/30/88/168/268/388 钻石）与赠送文案一致。
4. 三个合规弹窗的标题、按钮文案、配色与源界面一致。
5. 红中牌面与万/筒/条同尺寸同质感，牌桌可见「中」字牌。
6. 音效触发点覆盖发牌、摸牌、出牌、碰、杠、胡、过、倒计时、结算。
7. 横屏 1334×750 下无裁切、无重叠、无滚动条；竖屏设备按比例缩放不拉伸。
